# CLAUDE.md

This workspace builds a VS Code alternative for editing OpenEdge ABL: nvim, Claude Code and a bash
terminal in one tmux window. Goals, achievements, to do and gaps with vscode-abl: `PROJECT-PLAN.md`.
User docs: `USER-GUIDE.md` (getting started, all features, keys); admin/repo overview: `README.md`.
Progress and test results: `setup-notes.md`; read it first when resuming ("do next").

## Layout

- `nvim/`: dedicated nvim config, linked as `~/.config/nvim-abl`, run with `NVIM_APPNAME=nvim-abl`.
  Entry `init.lua`, modules in `lua/abl/`, plugins (lazy.nvim) in `lua/abl/plugins/`.
  ABL: `lua/abl/abl.lua` (filetype + language server), `ftplugin/abl.lua`, `syntax/abl.lua`.
- `tmux/tmux.conf`, `tmux/abl-tmux.sh`: separate tmux server (`tmux -L abl`); launcher linked as `~/bin/abl-tmux`.
  `tmux/abl-open.sh`: Ctrl+click on a file name opens it in nvim (via `$ABL_NVIM_SOCKET`).
- `fetch-tools.sh`: downloads the latest tmux (tmux/tmux-builds, static) and nvim (release tarball, in
  `tools/nvim`, linked as `tools/bin/nvim`; not the AppImage, which needs FUSE) into `tools/bin`
  (not in git; deploy.sh copies it). The launcher and install.sh prefer them over the native packages
  (`ABL_TMUX_NATIVE=1`: native) and export `ABL_TMUX_BIN`/`ABL_NVIM_BIN`; tmux.conf uses `@abl_tmux`.
  It also unpacks vscode-abl from the Marketplace into `tools/riversidesoftware.openedge-abl-lsp-<ver>-linux-x64`;
  `abl.lua` (and `abl-tmux -V`) take the newest of that and `~/.vscode*/extensions`, VS Code's on a tie.
- `install.sh`: per user, creates the links and installs the plugins. `deploy.sh [target]`: copies the
  repo to `/opt/abl-tmux` (or target) for all users. `RELEASE-NOTES.md`: user-visible changes per version.
- `nvim/cheatsheet.md` (`lua/abl/cheatsheet.lua`): opens when nvim starts without files; most used keys first.
- `claude/abl-tmux.md`: passed to claude with `--append-system-prompt-file`.
- `nvim/lua/abl/tasks.lua`: VS Code tasks (Ctrl+Alt+T). `nvim/lua/abl/vscode.lua`: reads VS Code's JSONC files.
- `openedge-project.json`, `src/`, `dump/`: a small ABL project to test against, not in git. `.builder/`
  and `tty/` are generated by the language server (state and r-code).

## Rules

- Never touch the user's normal setup: `~/.config/nvim`, `~/.tmux.conf`, `~/bin/claude-tmux.sh`.
- Keep the nvim config lean: copy only what's needed, no bloat. Keys should feel familiar to VS Code
  users without breaking vi defaults; update the key tables in `USER-GUIDE.md` and `nvim/cheatsheet.md` when changing keys.
- Add user-visible changes to `RELEASE-NOTES.md` (under a new version when a deploy follows) and
  `USER-GUIDE.md`; keep "Achieved" and "To do" in `PROJECT-PLAN.md` current.
- nvim is 0.12 (snap): use `vim.lsp.config`/`vim.lsp.enable`, nvim-treesitter `main` branch.

## Testing

- Test headless: `NVIM_APPNAME=nvim-abl nvim --headless -c "luafile <script>"`, or drive a real nvim in a
  separate tmux server (`tmux -L claudetest`) and read it with `capture-pane`. Kill that server afterwards.
- A session the launcher starts (e.g. `ABL_TMUX_SOCKET=claudetest2 tmux/abl-tmux.sh` inside an outer test
  tmux) runs on `tools/bin/tmux` (3.7c): talk to it with that binary, the native 3.2a client gets "server
  exited unexpectedly". Simulate keys and clicks by sending the raw bytes to the outer pane
  (`send-keys -l $'\e1'`, SGR mouse `$'\e[<16;x;yM'`); plain `send-keys` to the inner pane skips bindings.
- **Never start nvim-abl in a real workspace (this directory, `~/workspaces/*`), not even headless for a
  non-ABL test:** nvim starts the ABL server as soon as its cwd has an `openedge-project.json`. Use a copy
  of the project under the scratchpad, or a directory without one.
- **Test the ABL language server in a copy of the project under the scratchpad, never in this directory.**
  Only one server per project compiles; others log "Project already started in another window,
  compilation will be handled there" and hand off to it, which skews results and disturbs the user's
  running session.
- The server ignores LSP `exit`; `abl.lua` kills it after `exit` and on `VimLeavePre`. Killing nvim
  (or its tmux server) skips that, so check `ps -ef | grep abl-lsda` and stop any server you left behind.
  Leave the user's VS Code servers and other users' servers alone.
- The user's live nvim can be inspected read-only via its socket:
  `nvim --server /run/user/$(id -u)/nvim-abl.<pid>.0 --remote-expr '...'`.

## Logs

- `~/.local/state/nvim-abl/lsp.log` (`:LspLog`): language server output, tagged `[ERROR]` regardless of level.
  `vim.lsp.log.set_level("debug")` adds the RPC traffic.
- `.builder/clientlog0.log`, `.builder/stdout0.log`: the OpenEdge build AVM.

## Environment

- tmux/nvim: bundled `tools/bin` (3.7c / 0.12.6) or native (`/usr/bin/tmux` 3.2a, snap nvim 0.12.5).
- OpenEdge: `/usr/oe128` (12.8, = `/usr/oe12811`), `/usr/oe122`; `DLC=/usr/dlc`. Runtimes are listed in `abl.lua`.
- ABL language server: `~/.vscode-server/extensions/riversidesoftware.openedge-abl-lsp-*` (unlicensed; the user
  follows the pre-release channel, 1.37.x) or `tools/` (Marketplace stable, 1.36.0).
- tree-sitter-abl: `~/projects/tree-sitter-abl` (no highlight queries; parses too little real code to use yet).
